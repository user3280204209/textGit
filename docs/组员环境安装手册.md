# 组员环境安装手册（零基础版）

> 目标读者：**从没配过开发环境的同学**。
> 按顺序做，每步都有验收方法。做错不要紧，每步都能单独重来。
>
> 全程约 **30~60 分钟**，其中大部分时间是在下载和等待安装。

---

## 开始之前：先明确你要装什么

全组**人人必装**这 5 样：

1. Miniconda（自带 Python 3.13）
2. Git
3. Node.js
4. VS Code
5. LLM API Key（找技术负责人要）

**不要**自己额外装别的（尤其不要装 torch、faiss、ollama，详见《工具链清单》）。

---

## 第 0 步：确认你的电脑

- Windows 10 或 11（64 位）
- 至少 **15 GB** 可用磁盘空间
- 能正常上网

> Mac 同学：命令换成 macOS 版本（用 Homebrew），或直接找技术负责人协助。

---

## 第 1 步：安装 Miniconda

### 为什么需要它

Python 有很多版本，不同项目要的版本不同。Miniconda 让你**在同一台电脑上并存多个 Python 环境**，互不干扰。没有它，你装了 A 项目的包可能弄坏 B 项目。

### 操作

1. 打开 https://docs.conda.io/en/latest/miniconda.html
2. 下载 **Windows 64-bit (Miniconda3 Latest)** 的 `.exe`
3. 双击安装，**关键选项**：
   - 选 **"Just Me (recommended)"**
   - 安装路径**不要有中文和空格**，建议 `D:\Miniconda3` 或默认路径
   - 到 "Advanced Options" 时，**勾选** "Add Miniconda3 to my PATH environment variable"
     （不勾的话后面命令行找不到 conda）
   - 勾选 "Register Miniconda3 as my default Python"

### ✅ 验收

**关掉所有命令行窗口**，重新打开一个（重要！环境变量要重载），然后输入：

```powershell
conda --version
```

看到类似 `conda 25.x.x` 就成功了。

❌ 如果提示"不是内部或外部命令"：
- 说明 PATH 没配好。重新安装并**确保勾选了 Add to PATH**；
- 或者手动把 `你的安装路径\Scripts` 和 `你的安装路径\condabin` 加进系统环境变量 PATH。

---

## 第 2 步：安装 Git

### 为什么需要它

Git 是**多人协作的命脉**。没有它，两个人同时改一个文件就会互相覆盖，
出了问题也回不到之前的版本。**这不是可选项。**

### 操作

1. 打开 https://git-scm.com/download/win
2. 下载 64-bit 安装包，双击运行
3. 一路 Next 即可，**只有一处建议改**：
   - 遇到 "Adjusting your PATH environment" 时，选
     **"Git from the command line and also from 3rd-party software"**（默认选项）

### ✅ 验收

新开一个命令行窗口：

```powershell
git --version
```

看到 `git version 2.x.x` 即成功。

### 还需做一次：配置你的身份

Git 需要知道"你是谁"，每次提交都会记录：

```powershell
git config --global user.name "你的姓名"
git config --global user.email "你的邮箱@example.com"
```

> 📌 姓名请用真名（老师要看到谁做了什么）。邮箱用你注册 GitHub 的那个。

---

## 第 3 步：安装 Node.js

### 为什么需要它

前端（React + Vite）跑在 Node.js 上。

### 操作

1. 打开 https://nodejs.org/
2. 下载 **LTS 版本**（左边那个绿色按钮）
3. 双击安装，一路 Next（默认选项就行）

### ✅ 验收

**新开命令行窗口**：

```powershell
node -v
npm -v
```

应分别输出 `v20.x.x` 或更高 和 `10.x.x`。

---

## 第 4 步：启用 pnpm

### 为什么用它

npm 是 Node 自带的包管理器，但 pnpm 更快、更省磁盘，
而且**锁文件更严格**，能减少"我这能跑你那跑不了"的问题。

### 操作

```powershell
corepack enable
corepack prepare pnpm@9.15.0 --activate
```

> `corepack` 是 Node 自带的工具，不用额外下载。

### ✅ 验收

```powershell
pnpm -v
```

输出 `9.x.x` 即成功。

❌ 如果 `corepack` 命令不存在：说明 Node 版本太老（低于 16.9）。重装最新 LTS。

---

## 第 5 步：安装 VS Code

### 操作

1. 打开 https://code.visualstudio.com/
2. 下载安装，一路 Next
3. **建议勾选**（安装向导最后一页）：
   - "Add to PATH"
   - "Open with Code"（右键菜单，方便）

### 安装必需插件

打开 VS Code 后，按 `Ctrl+Shift+X` 打开扩展面板，搜索并安装：

| 插件名 | 作用 | 必需？ |
|---|---|---|
| `Python` | Python 语言支持 | ✅ 必需 |
| `Pylance` | 智能提示 | ✅ 必需 |
| `Ruff` | Python 代码检查与格式化 | ✅ 必需 |
| `EditorConfig for VS Code` | **统一缩进和行尾** | ✅ **必需** |
| `ESLint` | 前端代码检查 | ✅ 必需 |
| `Prettier` | 前端格式化 | ✅ 必需 |
| `Markdown Mermaid` | 预览思维导图 | 可选 |
| `Chinese (Simplified)` | 中文界面 | 可选 |

> **EditorConfig 为什么必需？**
> Windows 和 Mac 的换行符不一样（CRLF vs LF）。不统一的话，
> 你改一行代码，Git 会显示整个文件都变了，评审根本没法看。

## 第 7 步：一键初始化环境

前面装的都是"工具"，现在装"项目依赖"。

```powershell
# 在仓库根目录（textGit）下
pwsh -File scripts/setup.ps1
```

> 如果提示 `pwsh` 不认识，用：
> ```powershell
> powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
> ```
> 或者直接**双击 `scripts\setup.bat`**。

这个脚本会自动做完 4 件事：

1. 检查你必需的工具装齐了没（缺什么会明确告诉你）
2. 创建名为 `learnagent` 的 Python 环境
3. 安装后端依赖
4. 安装前端依赖

**首次运行需要 3~8 分钟**，大部分时间在下载。看到绿色"初始化完成"就好。

### ❌ 如果失败

脚本会告诉你卡在哪一步。最常见的是网络超时：

```powershell
conda activate learnagent
pip install -r backend\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 第 8 步：配置 API Key（关键）

项目要调用大模型，必须填 Key。

### 操作

1. 打开文件 `backend\.env`（用记事本或 VS Code）
   - 如果这个文件不存在，先把 `backend\.env.example` 复制一份改名为 `.env`
2. 找到这一行：

```
LLM_API_KEY=sk-在这里填你的真实Key
```

3. 把 `sk-在这里填你的真实Key` 替换成技术负责人给你的真实 Key
4. 保存

### ⚠️ 三个常见坑

| 坑 | 说明 |
|---|---|
| **加了引号** | ❌ `LLM_API_KEY="sk-xxx"` → ✅ `LLM_API_KEY=sk-xxx` |
| **前后有空格** | ❌ `LLM_API_KEY= sk-xxx ` → ✅ 紧凑写 |
| **文件名不对** | Windows 默认隐藏扩展名，可能实际是 `.env.txt`。在文件夹里开"显示文件扩展名"确认 |
| **提交到 Git** | **绝对不要！** `.env` 已在 `.gitignore` 里，不要强制添加 |

```powershell
# 在仓库根目录（textGit）下（会自动开两个窗口）
pwsh -File scripts/dev.ps1
```

会弹出两个新窗口：一个跑后端，一个跑前端。

### ✅ 验收

| 检查项 | 地址 | 期望看到 |
|---|---|---|
| 后端文档 | http://127.0.0.1:8000/docs | Swagger 接口列表 |
| 环境自检 | http://127.0.0.1:8000/api/env-check | 各项 `ok: true` |
| 前端页面 | http://127.0.0.1:5173 | 脚手架自检页，显示"后端状态"和"环境自检" |

**三个都正常 = 你的环境彻底配好了。** 🎉

## 出问题了怎么办

### 排查顺序（按这个来，不要瞎试）

1. **看 `http://127.0.0.1:8000/api/env-check`**
   它会明确告诉你哪一项没通过、怎么修。

2. **看后端窗口的日志**
   错误信息通常在最后几行。

3. **确认环境激活了没**
   ```powershell
   conda env list        # learnagent 前面应该有 *
   ```
   没有 `*` 就执行 `conda activate learnagent`

4. **确认在正确的目录**
   - 启动后端要在 `backend` 目录
   - 前端命令要在 `frontend` 目录

5. **还是不行 → 把这三样发到群里**
   - 你执行的**完整命令**
   - **完整报错信息**（截图或复制文字，不要只发"跑不起来"）
   - `conda list` 的输出

### 常见错误速查

| 报错 | 原因 | 解决 |
|---|---|---|
| `conda : 无法将"conda"项识别为...` | PATH 没配 / 没重开窗口 | 关掉所有命令行重新打开；仍不行则重装 Miniconda 并勾选 Add to PATH |
| `ModuleNotFoundError: No module named 'fastapi'` | 环境没激活 / 依赖没装 | `conda activate learnagent` 后重跑 `pip install -r backend\requirements.txt` |
| `503 未检测到 LLM_API_KEY` | Key 没填 | 检查 `backend\.env` |
| 前端"无法连接后端" | 后端没起 / 端口占用 | 看后端窗口；`netstat -ano \| findstr :8000` |
| `pip` 下载极慢 | 默认源在国外 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| `pnpm : 无法将...识别` | 没启用 corepack | `corepack enable` |
| 端口 8000 被占用 | 有别的程序占着 | `netstat -ano \| findstr :8000` 找到 PID，任务管理器结束它 |
| Git 显示整个文件都改了 | 行尾符不一致 | 确认 `.editorconfig` 存在；执行 `git add --renormalize .` |

## 附：日常使用速查

```powershell
# ---- 每次开始工作 ----
git pull                          # 先拉别人的改动
conda activate learnagent
pwsh -File scripts/dev.ps1        # 启动前后端

# ---- 提交代码 ----
git status                        # 看改了哪些文件
git add <文件名>                   # 添加，别用 git add . 盲加
git commit -m "feat: 完成了XXX功能"
git push

# ---- 结束工作 ----
# 关掉那两个服务窗口，或各自按 Ctrl+C
```

详细的协作规范（分支怎么开、提交信息怎么写、如何提 PR）见
👉 [`协作规范.md`](协作规范.md)

## 附：卸载/重来

环境配坏了不用慌，可以只重建 Python 环境：

```powershell
conda env remove -n learnagent
# 然后重新执行
pwsh -File scripts/setup.ps1
```

前端依赖坏了：

```powershell
cd frontend
rmdir /s /q node_modules
pnpm install
```
